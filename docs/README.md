## 3. 同步规则

1. **文档先行**：改行为先改 02/03/04，再改代码；每步提交同步更新受影响的文档（05 §9）。
2. **先改权威再改下游**：FR/AC 动 02；设计裁决动 03 §0；接口动 04；流程动 05；测试口径动 06；勾选状态动 07。
3. **偏差必须登记**：下游与上游不一致时，在对应「偏差」表写编号、裁决、关闭条件；关闭时写日期与提交号（或「2026-11-19 文档门禁」）。
4. **不写未发生的结论**：安装冒烟、手工 AC、性能数字未执行时一律标「待执行」，不得写「已验证」（06 §8.4）。
5. **每次文档变更记入 [docs/CHANGELOG](CHANGELOG.md)**；产品/仓库级变更记根 [CHANGELOG](../CHANGELOG.md)。
6. **链接必须可解析**：相对链接指向真实文件；章节锚点使用 GitHub 规则。`npm run verify` 中的文档契约测试会检查关键表与链接。

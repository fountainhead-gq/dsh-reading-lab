## 1. 结论

**t11 当时的判定：v0.1.0 未达发布门禁，不建议合并 `main` 或打 `v0.1.0`。**

失败项分两类：

- **实现缺陷**：QA-11-01（多 workspace 下 `/health` 503，blocker，已修）、QA-11-04/05/06（导入命名与导出路由契约，中低危，已修）。
- **范围缺口**：PDF 导入（FR-05）与卡片详情/引用跳转（FR-09）未实现。t11 建议「补实现或明确收窄 v0.1」，captain 选择收窄：两项移至 v0.2（t13/t14），见 [02 §6 范围变更记录](02-requirements.md) 与 [07 §3.0](07-checklist.md)。

收窄后的 v0.1 口径：M1 面板壳 + EPUB 导入/分块 + 导图生成与只读画布；PDF 只要求返回 `E_UNSUPPORTED{reason:'pdf-pending'}` 且不产生半成品。

## 9. 教训

1. **可选服务不能直接点属性**。Cordis 的 `ctx.foo` 在未 inject 时抛错，而不是返回 `undefined`；一个探测分支就能让整个插件 503。已升级为设计约束（D-03-13）。
2. **能力声明必须与实现同源**。`/health.capabilities` 宣告了什么，对应路由就必须做到；否则客户端会进入半可用状态。
3. **headless agent 不能作为出图验收环境**。`queued` 不是成功；验收要看到 `map.json` 的 `generatedAt` 变化与节点数变化。
4. **范围与文档必须同步**。t11 的 3 个 blocker 里 2 个是「文档承诺了、实现没排期」；收窄 v0.1 比假装完成更诚实。

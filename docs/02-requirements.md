## 1. 愿景

让「读一本书」在 DSH 里变成一件**可追溯**的事：导入 PDF/EPUB，得到一张按目录展开、每张卡片都带原文引用的思维导图；在卡片上直接追问 AI，答案回到引用；最后把导图、笔记与问答导出为开放格式。

一句话定位：**本地优先、引用优先的阅读分析工作台，AI 过程发生在会话里而不是黑盒里。**

不做「又一个 AI 摘要器」。判断需求是否该做的三条标准：

1. 是否让**引用**更可信（能回到具体段落，而不是「根据全文」）。
2. 是否让**结构**更清晰（目录 → 章节 → 论点，而不是一段摘要）。
3. 是否让**产物**可带走（Markdown/OPML/JSON，而不是锁在插件里）。

## 2. 用户与场景

### 2.1 目标用户

| 用户 | 特征 | 关键诉求 |
|---|---|---|
| 研究者 / 研究生 | 大量英文论文与专著，需精读与综述 | 快速搭结构、引用可核查、笔记能进入既有工作流（Markdown/OPML） |
| 产品 / 咨询从业者 | 读行业报告、白皮书，输出结论 | 一本书一次读完、提炼论点、导出给别人看 |
| 深度阅读爱好者 | 非虚构为主，跨书比较 | 读得进去、记得住、能回看当时的想法 |

### 2.2 核心场景

**S1 一本书变一张图（主路径）**
导入一本 EPUB 或文本型 PDF → 自动解析目录与正文 → 会话 agent 生成书卡、章节卡、论点卡 → 画布上平移缩放浏览 → 点卡片看摘要与引用 → 点引用回到原文段落。

**S2 在卡片上追问**
选中一张卡 → 右浮层出现快捷指令（深入探索 / 解释 / 简化 / 举例）→ 提问进入当前会话 → agent 基于该卡的摘要与原文块回答 → 回答写入卡片线程，同时留在会话流里 → 可继续追问。

**S3 形成研究笔记**
对全书生成研究笔记（主题脉络、核心论点、术语表、阅读建议）→ 每条结论带引用 → 与导图一起导出 Markdown，或把导图导出 OPML 进 XMind/幕布。

**S4 失败与边界**
导入扫描版 PDF → 明确提示「无文本层，暂不支持 OCR」；导入加密文档 → 标记「受保护」；解析中断 → 书库保留条目，可重试；模型未配置 → 浏览与导出可用，提问入口禁用并说明原因。

| US-04 | 作为研究者，我想在卡片上直接问 AI，并保留这段问答 | P1 | v0.2 |

## 3. 术语

| 术语 | 定义 |
|---|---|
| 书（book） | 一次导入产生的实体，含原文件、元数据与全部产物；`bookId` 稳定且唯一 |
| 块（chunk） | 解析后按章节/段落切分的正文单元，带 `chunkId`、`charRange`、`pageRange`、`headingPath` |
| 卡片（node） | 导图上的一个节点，对应书/章/节/论点；含标题、摘要、引用、追问建议 |
| 引用（citation） | 卡片或笔记指向 `chunkId` 的定位符；渲染前必须校验存在 |
| 线程（thread） | 某张卡片（或全书）下的问答记录，落盘 `threads.json` |
| 会话留痕 | 提问与回答同时出现在 DSH 会话流中，可回看、可继续 |
| 研究笔记 | 全书视角的结构化笔记，落盘 `notes.md` |

## 4. 功能需求

优先级：P0 = v0.1 必须；P1 = v0.2 必须；P2 = v0.3。每条验收都是**可观察行为**，不绑定实现。

### FR-01 插件入口与主面板（P0 / v0.1）

- 侧栏出现「阅读实验室 / Reading Lab」图标；点击打开主面板，再点不产生第二个实例。
- 主面板为空态时显示导入引导；有书时恢复上次选中的书与画布视口（同一会话内）。
- 面板 id、图标 id、bundle 行 id 一致，均为 `reading-lab`（DR-01、DR-06）。

**验收**：点击侧栏图标，中心区切换到本插件主面板；切到会话再切回，选中的书与缩放级别不重置；空态有可点击的「导入」按钮。

### FR-02 书库列表（P0 / v0.1）

- 左栏列出全部书：封面缩略图（可缺省）、书名、作者、格式徽标（PDF/EPUB）、状态（排队/解析中/就绪/不支持/失败）、导入时间。
- 默认按最近打开排序；支持重命名、删除（二次确认）、重新生成导图。
- 解析中的条目显示进度（页/章），不阻塞其他书浏览。

**验收**：50 本书时列表可滚动且不卡顿；删除后条目与 `reading/books/<id>/` 同时消失；重命名只改元数据，不改原文件名。

### FR-03 导入（P0 / v0.1）

- 支持文件选择与拖放；扩展名与魔数双重校验，仅接受 `.epub` 与 `.pdf`。
- 限制：单文件 ≤100 MB、PDF ≤2000 页、解压后 EPUB 文本 ≤50 MB；超限在解析前拒绝。
- 同一文件重复导入（按 SHA-256）提示「已存在」并跳到已有书，不产生副本。
- 状态机：`queued → parsing → ready | unsupported | failed`；失败保留条目与原因，可重试或删除。
- 原文件复制进 `reading/books/<bookId>/`，导入完成后原文件可删除而不影响阅读。

**验收**：EPUB 与 PDF 各导入一本均进入 `ready`；把 `.txt` 改名为 `.pdf` 会被拒绝且不建目录；重复导入同一文件只保留一本；解析失败时目录内无 `map.json`、无半成品节点。

### FR-04 EPUB 解析（P0 / v0.1）

- 读 `META-INF/container.xml` → OPF，取 title/creator/language/cover；缺 title 时回退文件名。
- 按 `spine` 顺序取 XHTML；章节标题优先 nav，其次 NCX，最后「第 N 章」。
- 正文抽为纯文本段落，保留段落边界；XHTML 净化（去脚本、事件属性、远程资源）后再进渲染层。
- 兼容 EPUB 2（NCX）与 EPUB 3（nav）；DRM/加密条目判为 `unsupported`。

**验收**：夹具 EPUB（2 章）解析出正确 title/creator 与 2 章正文；含 `<script>` 的夹具在渲染层无脚本执行、无远程请求；损坏的 ZIP 给出 `E_PARSE` 且不崩溃。

### FR-05 PDF 解析（P0 / v0.1）

- 逐页 `getTextContent`，保存每页文本与页数；取 PDF 元数据 title（可缺省）。
- 中文：`cMapUrl` 与 `standardFontDataUrl` 固定指向包内资源，禁止 CDN；确保中文与符号字体正确。
- 扫描版判定：抽样页（首/中/末各 1 页，不足 3 页则全取）平均有效字符 <20，判 `unsupported`；不为此预读全书。
- 加密 PDF 捕获密码异常，判 `unsupported`，提示「受保护文档」；不做解密。
- 不做 OCR、不做版面还原、不渲染页面图像。

**验收**：2 页中文 PDF 抽检 5 段文本与原文一致；10 页英文论文抽取标题与正文正确；扫描版 PDF 在 10 s 内被判定并给出可读原因；加密 PDF 不进入 `parsing` 卡死。

### FR-06 分块与定位（P0 / v0.1）

- 按章节/标题路径切块，块长目标 800–1500 字，硬上限 2000 字、下限 100 字（过短并入相邻块）。
- 每块记录：`chunkId`（`<bookId>:c<seq>`）、`charRange`、`pageRange`（PDF）、`headingPath`、`text`。
- 分块确定性：同一文件重复导入，`chunkId` 与块边界一致。
- 全书块数上限 20,000；超限提示并拒绝生成导图（仍可浏览）。

**验收**：任取一块，`text` 与原文抽取文本的 `charRange` 一致；同一文件两次导入的块数与 id 完全一致；不足 100 字的尾块被合并。

### FR-07 导图生成（P0 / v0.1）

- 由会话 agent 调用 `reading.map` 生成：书卡为根，向下 2–4 层（章 → 节 → 论点）。
- 每个非根节点必须有 1–3 条引用，指向真实 `chunkId`；叶节点摘要 40–120 字。
- 每个节点生成 1–3 条追问建议（「我想知道…」），v0.2 起在浮层展示。
- 工具输出校验：未知 `chunkId`、空引用、摘要超长 → 该节点拒绝；整图校验失败重试一次，仍失败则保留旧图并报 `E_CITATION`。
- 写入 `map.json` 采用临时文件 + 原子替换；生成中旧图可继续浏览。
- 进度通过会话流节点（`conversation.chat.node`）与面板状态同时呈现。

**验收**：EPUB 与 PDF 各生成一张图，根节点为书名，叶节点均带 ≥1 条可点击引用；手工注入一个不存在的 `chunkId`，生成被拒绝且旧图不变；生成过程中切换书再回来，进度仍可见。

### FR-08 画布（P0 / v0.1）

- 分栏卡片树布局：书卡居中，章节向左右展开，贝塞尔连线；节点按层级配色（用主题 token）。
- 平移：拖拽空白处或方向键；缩放：滚轮 / `+` `-` / 按钮，范围 25%–200%；「适应窗口」一键全览。
- 选中：单击卡片出现描边与详情；`Esc` 取消；展开/收起子树。
- v0.1 只读：不拖拽改结构、不编辑文本。

**验收**：200 个节点时拖动/缩放 p95 帧间隔 ≤33 ms（本机采样）；「适应窗口」后全部节点可见；切到会话再切回后视口与选中恢复；键盘可完成平移、缩放、选中与取消。

### FR-09 卡片详情与引用跳转（P0 / v0.1）

- 点卡片打开详情：标题、摘要、引用列表（引用计数与角标一致）、追问建议（v0.2 展示）。
- 点引用：打开原文视图并滚动到对应块，高亮 3 s；PDF 显示页码，EPUB 显示章节标题。
- 详情不遮挡选中卡；浮层/详情打开时画布仍可平移。
- 引用无法定位时不渲染该条，并在详情标注「引用失效」，不静默跳到书首。

**验收**：任取一条引用，点击后原文视图显示的文字与 `chunkId` 对应块一致；引用计数等于列表条数；删除 `chunks.json` 后打开详情不崩溃，显示引用失效。

### FR-10 研究笔记（P1 / v0.2）

- `reading.notes` 生成全书笔记，固定五节：主题脉络、核心论点、术语表、阅读建议、开放问题。
- 有内容的每节至少 1 条引用；某节无内容时写「本书未形成该部分」，不编造。
- 落盘 `notes.md`（Markdown，引用以 `chunkId` 链接形式）；面板内可读、可复制。
- 支持单节重新生成（v0.3 开放到 UI）。

**验收**：笔记五节齐全，引用不少于 5 条且全部可定位；重新生成不改变 `map.json`；`notes.md` 在面板与导出中内容一致。

### FR-11 询问 AI（P1 / v0.2）

- 入口：选中卡片后的悬浮按钮 / 快捷键；右浮层从面板右侧滑出，不遮住选中卡。
- 快捷指令：深入探索、解释、简化、举例；另有自由输入框与 1–3 条追问建议。
- 上下文：选中节点摘要 + 3–5 条相关块原文（总长 ≤6000 字）+ 书名/作者/章节路径；无选中时用全书概览。
- 发送经 Host 的 `agent.followup` 注入当前会话（`commands.execute` 只执行斜杠命令、不送模型）；回答流式出现在会话流，浮层同步展示。
- 无活动会话或模型未配置时，输入禁用并说明「请在会话中配置模型后重试」。
- 同一线程同时只允许一个进行中的提问；可停止（中断信号）。

**验收**：选中一张卡问「这个论点成立吗」，回答含 ≥1 条引用且可点回原文；会话流出现同一条提问与回答；未选中卡片时提问仍可用全书上下文；连续快速点击发送不会产生两条并发请求。

### FR-12 线程与留痕（P1 / v0.2）

- 每本书 `threads.json`：线程按 `nodeId`（或 `book`）分组，消息含 `id`、`role`、`text`、`citations`、`createdAt`、`status`、`messageId`（若可关联）。
- 提问进入会话流，回答写回线程；刷新/重启后线程恢复，顺序稳定。
- 删除书时线程一并删除；导出时可选「附带问答精选」。
- 不重复注入：面板重渲染、切换书再回来，不重复发送同一条提问。

**验收**：提问 → 关闭 DSH → 重启 → 打开同一本书，线程与引用完整；会话流中同一条问答只出现一次；删除书后 `threads.json` 随目录删除。

### FR-13 导出（P1 / v0.2）

| 格式 | 内容 | 验收 |
|---|---|---|
| Markdown | 研究笔记 + 导图大纲（含引用 `chunkId`）+ 可选问答精选 | 标题层级与导图一致；引用可读；无 HTML 注入 |
| OPML | 导图节点树（标题 + 摘要 + 引用 id） | 可被 XMind/幕布导入，层级不丢 |
| JSON | `meta + map + notes 索引` 完整快照，带 `schemaVersion` | 通过仓库内 JSON Schema 校验；`map` 部分字段与 `map.json` 一致 |

- 产物写入 `reading/exports/`，文件名 `<书名>-<yyyyMMdd-HHmmss>.<ext>`；重名自动加序号。
- 导出不改动 `map.json` / `notes.md`；失败不留半文件（临时文件 + 原子替换）。

**验收**：三种格式各导出一次，文件存在于 `reading/exports/`；OPML 在 XMind 中打开层级正确；JSON 校验通过；导出后源文件哈希不变。

### FR-14 书库生命周期（P1 / v0.2）

- 删除：二次确认，取消进行中的解析/生成，删除整目录；失败给出原因并保留可重试状态。
- 重命名：只改 `meta.json` 的显示名，原文件与 `bookId` 不变。
- 重新生成：v0.2 支持整图重生成，v0.3 开放单节点重生成；生成失败保留旧产物。
- 重新解析（用户显式触发）：覆盖产物前先备份 `map.json` 为 `map.bak.json`（保留 1 份）；重复导入仍按 FR-03 跳到已有书，不覆盖。

**验收**：删除解析中的书不残留进程与目录；重命名后引用与线程仍指向同一 `bookId`；重新生成失败后旧图仍可打开。

### FR-15 错误与恢复（P0 / v0.1）

统一错误码与用户文案（中英）：

| 码 | 触发 | 用户看到 | 恢复 |
|---|---|---|---|
| `E_FORMAT` | 非 EPUB/PDF 或魔数不符 | 「不支持该格式」 | 换文件 |
| `E_TOO_LARGE` | 超体积/页数 | 「文件超出 100 MB / 2000 页限制」 | 拆分后重试 |
| `E_ENCRYPTED` | 加密/DRM | 「受保护文档，暂不支持」 | — |
| `E_SCANNED` | 无文本层 | 「扫描版 PDF 暂不支持 OCR」 | 换文本版 |
| `E_PARSE` | 结构损坏 | 「解析失败：<原因>」 | 重试/删除 |
| `E_AGENT` | 会话中断/模型失败 | 「生成中断，可重试」 | 重试 |
| `E_CITATION` | 引用校验失败 | 「生成结果引用无效，已保留上一版」 | 重新生成 |
| `E_IO` | 工作区写入失败 | 「无法写入工作区，请检查权限」 | 检查目录 |

**验收**：逐条构造触发条件，UI 显示对应文案，不出现堆栈；失败后书库仍可操作；日志写入 `reading/books/<id>/import.log`，不含正文。

## 5. 非功能需求

| 编号 | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-01 | 性能 | 50 本书冷启动面板 ≤800 ms；5 MB EPUB 解析 ≤2 s；50 MB/500 页 PDF 解析 ≤30 s；200 节点平移/缩放 p95 帧 ≤33 ms；导图首次布局 ≤500 ms | 本机基准脚本 + 手工采样，记录在 [06 测试](06-test.md) |
| NFR-02 | 内存 | 100 MB PDF 解析峰值 ≤1 GB；按页流式处理，不持有全部页面文本项 | `process.memoryUsage` 采样 |
| NFR-03 | 数据安全 | 所有写入原子化（临时文件 + rename）；崩溃后不出现半写 JSON；`schemaVersion` 可迁移 | 杀进程注入测试 |
| NFR-04 | 离线 | 导入、解析、浏览、引用、导出在断网下可用；仅 AI 提问依赖模型与网络 | 断网手工验收 |
| NFR-05 | 隐私 | 原文、笔记、线程只存本地工作区；无遥测；日志不含正文；除模型调用外不发网络请求 | 抓包 + 日志抽查 |
| NFR-06 | 兼容 | DSH ≥0.2.2-rc.1；以 0.2.2-rc.5 实测；Host 只用 Node 24 可用 API；不依赖浏览器 API | 版本矩阵 + `npm run check` |
| NFR-07 | 国际化 | 中/英 100% 文案走 locale；无硬编码 UI 文本；日期/数字按 locale | 切换语言逐屏检查；locale key 覆盖率脚本 |
| NFR-08 | 主题 | 只用 `--dsw-alias-*` 颜色 token；亮/暗主题自动跟随；正文对比度 ≥4.5:1 | 双主题截图 + 对比度检查 |
| NFR-09 | 可访问性 | 主面板全部操作可键盘完成；焦点可见；图标有 `aria-label`；画布可 Tab 进入选中节点并用方向键移动选择 | 键盘走查 + axe 检查 |
| NFR-10 | 安全 | EPUB XHTML 白名单净化；路径限制在 `reading/`；引用只接受已知 `chunkId`；禁远程资源 | 恶意 EPUB 夹具 + 路径逃逸用例 |
| NFR-11 | 可维护 | 解析/分块/布局/导出为纯函数并有单测；依赖锁定版本；许可证与 MIT 兼容 | `npm test` + 许可证清单 |
| NFR-12 | 可安装 | 安装不依赖运行时联网；锁文件指向 `registry.npmjs.org`；提供离线 tgz 兜底 | 干净环境安装演练 |

## 7. 决策记录

> 以下 7 项为需求方批复的基线，后续变更需在本文追加 DR 并说明影响。

### DR-01 UI 承载：完整主面板

- **决策**：用 `main` 槽位（key = `reading-lab`）承载全屏工作台，`sidebar.panellist`（id 相同）提供入口；聊天流只作为进度/结果的辅助呈现。
- **备选**：B 会话内嵌导图；C 右侧栏面板。
- **理由**：`main` 与 `panellist` 同 id 即联动，源码与先例均已证（[01](01-research.md) §2.2、§2.5）；右栏打开占视口 45%、上限 70%，1440 px 下中心区仅约 528 px（还要容纳会话与内边距），无法横向排布「书卡 + 多列章节卡」（§2.4）；会话内嵌会牺牲画布空间与平移手感。
- **影响**：主面板要自管左栏/画布/浮层布局；`shell.overlay` 仅用于全窗预览；面板状态需在同一会话内保持。

### DR-02 AI 引擎：Agent 原生

- **决策**：所有 LLM 工作经当前会话 agent 调用 `reading.*` 工具完成；插件不直接调用 `llm` 服务、不保存 API Key、不实现模型路由。
- **备选**：插件 Host 侧经 `llm` 服务流式直调，做后台批处理。
- **理由**：过程在会话流可见、可中断、可复现；复用 DSH 的模型路由、配额与鉴权；避免插件与 harness 两套模型配置。直调会黑盒化，且要重复实现路由与配额（[01](01-research.md) §2.3）。
- **影响**：提问依赖活动会话与已配置模型；无模型时只读与导出可用；大文件并行留到 v0.3，用 `subagents`/`workflowEngine` 在 A 方案内优化。

### DR-03 导图渲染：自绘 SVG 卡片树

- **决策**：用 DOM + SVG 自研分层分列布局与贝塞尔连线；v0.1 只读，v0.3 再加编辑。
- **备选**：markmap / d3-org-tree / React Flow 等现成图库。
- **理由**：参考图是「书卡 → 章节卡 → 论点卡」的分栏卡片，不是放射状脑图，现成库的样式与交互范式差异大，定制成本高于自绘（[01](01-research.md) §1.3）；自绘零新增依赖，布局可作为纯函数单测。
- **影响**：需自研平移/缩放/命中测试/键盘导航；节点数上限与性能预算写入 NFR-01；v0.1 不做拖拽改结构。

### DR-04 格式范围：EPUB 3 + 文本型 PDF

- **决策**：v0.1 同时支持 EPUB 3（兼容 EPUB 2 的 NCX）与文本型 PDF；扫描版 PDF 明确不支持 OCR，加密/DRM 文档标记为不支持。
- **备选**：EPUB 先行、PDF 后置；只做 PDF；接 OCR。
- **理由**：EPUB 5 ms、PDF 126–242 ms 的实测证明两条解析链都轻（[01](01-research.md) §3.1–§3.3）；论文以 PDF 为主、专著以 EPUB 为主，缺一条都会让主路径断掉；OCR 依赖模型/大包、错误率高，与 v0.1 的确定性目标冲突。
- **影响**：两套解析器统一到 chunk 模型；引入 pdfjs 约 35 MB（实测 36.6 MB）与 jszip/fast-xml-parser；设置 100 MB/2000 页阈值；中文 CMap 必须本地化。

### DR-05 存储：工作区 `reading/`

- **决策**：书与产物存 `<workspace>/reading/books/<bookId>/`（原文件、`meta.json`、`chunks.json`、`map.json`、`notes.md`、`threads.json`、`import.log`），导出存 `reading/exports/`；不引入数据库，`storageDomain` 仅作轻量索引。
- **备选**：插件私有数据目录；SQLite。
- **理由**：用户可见、可 git、可整目录拷贝、重装插件不丢；与 DSH「工作区即事实源」一致；`workspaceFiles` 提供 read/list/stat/changes，足够支撑（[01](01-research.md) §2.3）；先例插件也用 `node:fs`。
- **影响**：所有路径必须限制在 `reading/`；JSON 带 `schemaVersion`；写入原子化；删除书即删目录；不提供云同步。

### DR-06 命名：`dsh-reading-lab` / 阅读实验室

- **决策**：npm 包名 `dsh-reading-lab`；展示名中文「阅读实验室」、英文「Reading Lab」；bundle 行 id、面板 key、`sidebar.panellist` id 统一为 `reading-lab`；工作区目录 `reading/`；agent 工具前缀 `reading.`。
- **备选**：`reading`、`dsh-reader`、`reading-lab` 作为包名。
- **理由**：DSH 插件包以 `dsh-` 前缀标识；`reading-lab` 同时用于 slot id 可避免与通用 `reading` 冲突；展示名与 README/文档一致，便于插件管理器与 locale 呈现（[01](01-research.md) §2.2）。
- **影响**：`DESIGN.md` §4 示意图中的 `key="reading"` 以本决策为准改为 `reading-lab`；locale 的 `meta.title`、图标、命令 id 随之统一；用户界面不出现 `dsh-` 前缀。

### DR-07 提问交互：面板内右浮层 + 线程落盘 + 会话留痕

- **决策**：询问 AI 用主面板内右侧浮层（可收起/调整宽度），不占用 DSH 右栏；每本书线程落盘 `threads.json`；每次提问经 `agent.followup` 注入当前会话，回答同时写回线程并留在会话流。
- **备选**：DSH 右栏 `sidebar.right.pane.tab`；模态对话框；输入框内联追问。
- **理由**：截图 3 的浮层贴着画布、不遮选中卡；DSH 右栏是 session 级全局页签，宽度与层级都不符合（[01](01-research.md) §2.2、§2.4）；模态会打断画布操作，内联没有历史。`agent.followup` 是 DSH 注入一条用户消息并唤醒 agent 的公开通道，会话流天然留痕；`commands.execute` 只执行斜杠命令、不送模型，不能产生回答（04 D-03-08）。
- **影响**：浮层需处理焦点与 `Esc`；线程 schema 见 [04 接口](04-api.md)；无活动会话时提问禁用；同一线程串行提问；重渲染不得重复注入。

## 8. 非目标

以下事项**明确不做**，不要以「顺手」为由加入 v0.1–v0.3：

| 非目标 | 原因 |
|---|---|
| 扫描版 PDF / 手写 OCR | 依赖重、错误率高；v0.1 用「识别并拒绝」保证体验诚实 |
| 云同步、账号体系、多端 | 与本地优先定位冲突；工作区文件可由用户自行同步 |
| 移动端 / 独立 App | DSH 桌面端是唯一载体；Web 客户端随 DSH |
| DRM 移除 / 破解加密 | 合规风险；受保护文档只提示不支持 |
| 实时协作、评论、分享链接 | 单人深读工具；导出即可分享 |
| 全文翻译、TTS、播客、测验生成 | 竞品的「消费层」能力，不是本项目主线 |
| 网页剪藏、浏览器扩展、RSS | 导入只面向本地文件 |
| 学术文献管理（BibTeX、Zotero 集成、引用格式） | 导出 Markdown/JSON 后由外部工具处理 |
| 把批注写回 PDF/EPUB 原文件 | 原文件只读，产物独立存放 |
| 跨书全局搜索 | v0.3 只做单本书内搜索 |
| 插件内置模型密钥 / 直调 LLM | 见 DR-02 |

### 9.2 发布门禁

合并到 `main` 前必须全部通过：

1. `npm run check`：Host/Client 入口语法检查。
2. `npm test`：解析、分块、布局（v0.2 起加导出）纯函数单测；恶意 EPUB 与路径逃逸用例。
3. 解析夹具冒烟：2 章 EPUB、2 页中文 PDF、10 页英文 PDF、扫描版 PDF 各一条。
4. `npm pack --dry-run`：发布包包含 `src/`、`locale/`、`icon.svg`、`cordis.patch.yml`、`README`、`LICENSE`，不含测试夹具与临时文件。
5. 手工走查 AC-01～AC-04、AC-08、AC-09（v0.1）；v0.2 追加 AC-06、AC-07、AC-10。

命令与用例细节由 [06 测试](06-test.md) 固定；本表只定义「什么算通过」。

## 10. 假设与约束

- **运行环境**：DSH 0.2.2-rc.5 实测；`engines.dsh >= 0.2.2-rc.1`。低于该版本槽位签名可能不同，不承诺兼容。
- **模型**：提问依赖用户在 DSH 中已配置的模型与活动会话；插件不附带模型、不代管密钥。
- **网络**：安装依赖需要访问 `registry.npmjs.org`（默认镜像实测 403）；运行期除模型调用外不联网。
- **文件系统**：假定工作区可读写且空间充足（一本 100 MB 书 + 产物约 150 MB）；不支持只读工作区。
- **语言**：首版中/英；其他语言回退英文。
- **平台**：跟随 DSH 桌面端（Windows/macOS/Linux）；不在移动浏览器上适配画布手势。
- **上游变动**：DSH 槽位与服务可能随版本演进；升级 DSH 后先跑 [06 测试](06-test.md) 的兼容用例，再改实现。
